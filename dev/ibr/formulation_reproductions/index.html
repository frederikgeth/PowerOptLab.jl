Reproducing forward operation with optimisation

Start with the P–Q tutorial for the meaning of a feasible region, an operating relationship and an objective.

The formulation comparison table separates hardware feasibility from controller decisions. These cases test when optimisation can reproduce the forward algebraic model. Run them with julia --project=. scripts/formulations/ibr_reproductions.jl.

Independent feeder equilibria

Three balanced feeders have source voltages of 215, 230 and 259 V and 0.05 Ω phase resistance. The inverter has nonzero filter impedance and fixed losses. Both formulations use the same smooth average-voltage curves, source budget, sensing reference and balanced converter-current allocation. Hardware limits are inactive; the 259 V case has an active volt-watt ceiling. Maximising export then reproduces the forward dispatch to the declared approximation tolerance.

using PowerOptLab
include(joinpath(pkgdir(PowerOptLab), "scripts", "formulations", "ibr_reproductions.jl"))
rows = ibr_formulation_reproductions()
for row in rows.feeder
    @assert row.forward.solve.publishable && row.constrained.solve.publishable
    @assert row.p_error_W < .2 && row.q_error_var < .2
    @assert row.current_error_A < .001 && row.voltage_error_V < .001
end
[(source_V=r.voltage, delta_P_W=r.p_error_W, delta_Q_var=r.q_error_var,
  delta_I_A=r.current_error_A, delta_V_V=r.voltage_error_V) for r in rows.feeder]
3-element Vector{@NamedTuple{source_V::Float64, delta_P_W::Float64, delta_Q_var::Float64, delta_I_A::Float64, delta_V_V::Float64}}:
 (source_V = 215.0, delta_P_W = 0.0778347797090646, delta_Q_var = 0.02414625203266496, delta_I_A = 0.00012607605266232765, delta_V_V = 6.3038026395172115e-6)
 (source_V = 230.0, delta_P_W = 0.07789158284413134, delta_Q_var = 0.0, delta_I_A = 0.00011267517393775961, delta_V_V = 5.633758689782553e-6)
 (source_V = 259.0, delta_P_W = 0.045368288245526855, delta_Q_var = 0.0942902007864177, delta_I_A = 0.0001345516193146016, delta_V_V = 6.727581003460863e-6)

These are different solved feeder equilibria, not a replay at one model's voltage. Small differences remain because the forward path regularises the power-to-current conversion (here power_voltage_floor=1e-3 V) and uses smooth conservative selectors/backoff. The optimisation retains the curve equalities and inequalities directly. This test is conditional, not a theorem for arbitrary unbalanced networks, current targets or binding hardware constraints.

Saturated proportional current limiting

A lossless 6 kVA three-leg plant has $I_{max}=1.1(6000)/(3\cdot230)$ A. At fixed 230 and 207 V POC voltage, its raw request is 6000 W + j2640 var. The optimisation adds the controller's ray restriction $I_{phase}=t I_{phase,raw}$, $0\le t\le1$, then maximises $t$ under the physical capability inequalities. This additional relationship reproduces the proportional limiter; it is not an implication of a current inequality.

An independent lossless oracle is $t=\min(1,S_{max}/|S_{raw}|,3VI_{max}/|S_{raw}|)$. The optimiser agrees with this scale to $10^{-7}$; the forward model agrees within 0.4 W and 0.2 var, including its conservative smoothing/backoff.

for row in rows.proportional
    @assert row.forward.solve.publishable && row.optimisation.status.publishable
    @assert abs(row.optimisation.scale-row.analytic_scale) < 1e-7
    @assert row.p_error_W < .4 && row.q_error_var < .2
end
[(POC_V=r.voltage, scale=r.optimisation.scale, analytic=r.analytic_scale,
  delta_P_W=r.p_error_W, delta_Q_var=r.q_error_var) for r in rows.proportional]
2-element Vector{@NamedTuple{POC_V::Float64, scale::Float64, analytic::Float64, delta_P_W::Float64, delta_Q_var::Float64}}:
 (POC_V = 230.0, scale = 0.9153150369084321, analytic = 0.9153150324227657, delta_P_W = 0.14519869669311447, delta_Q_var = 0.06377110934181474)
 (POC_V = 207.0, scale = 0.9061618863566223, analytic = 0.9061618820985382, delta_P_W = 0.31110156688464485, delta_Q_var = 0.13676291883211888)

By contrast, VoltVarWattConstraints retains Q=2640 var and curtails more P under current saturation. The 207 V comparison and its regression intentionally preserve that difference. Maximising P alone does not reproduce a proportional limiter.

Sequence-priority allocation at a fixed measurement

The final cases have $U_1=230$ V, $U_2=10e^{j0.2}$ V, no zero sequence, and a 6 A conductor limit. A purely reactive negative-sequence admittance requests approximately 3 A, alongside a 3000 W positive-sequence request. For both priority=:power and :balance, the reserved sequence alone fits inside the conductor rating. Optimisation holds that sequence fixed and maximises the other sequence's scale. It agrees with both evaluate_exact and an independent phase-by-phase quadratic disk intersection.

for row in rows.sequence_priority
    @assert row.optimisation.status.publishable
    @assert abs(row.optimisation.scale-row.analytic_scale) < 1e-7
    @assert row.current_error_A < 1e-6
end
[(priority=r.priority, scale=r.optimisation.scale,
  delta_I_A=r.current_error_A) for r in rows.sequence_priority]
2-element Vector{@NamedTuple{priority::Symbol, scale::Float64, delta_I_A::Float64}}:
 (priority = :power, scale = 0.5721282695970161, delta_I_A = 3.055686385351305e-8)
 (priority = :balance, scale = 0.7082595254476922, delta_I_A = 2.99912574519817e-8)

This is a fixed-measurement allocation reproduction. It does not establish equivalence of independently solved sequence-control network equilibria, the reserved-sequence backoff when that sequence alone is infeasible, or carrier reserve closure. The test suite separately checks full feeder reproduction, physical margins, failed-solve masking and the intentional strict-Q mismatch.

Unbalanced feeders and LCL current targets

The extended cases solve both models on a feeder with $U_1=230$ V and $U_2=8e^{j0.2}$ V at the source and 0.05 Ω phase resistance. Their POC voltages are solved separately. The LCL cases use nonzero series impedances, a 30 µF midpoint capacitor and damping resistance. Both models have the same physical plant, a 3000 W DC source budget and a constant 600 var command. The reduced filter comparison removes the midpoint branch.

CaseExpected comparisonWhat must match
Unbalanced reduced filterAgreementBalanced converter current and total POC Q
LCL, grid-current targetAgreementBalanced grid current and total POC Q
LCL, converter-current targetAgreement after matching the Q locationBalanced converter current and Q formed from POC voltage and converter current
LCL, converter target versus strict POC QDeliberate differenceThe two models impose different Q relationships; current-allocation choice alone does not align them

The forward command is formed using its sensing voltage and its selected target current:

\[Q_{command}=\Im\sum_k U_{POC,k}I_{target,k}^*.\]

Total POC exchange instead uses grid-arm current. In these examples there is no separate POC shunt, so $Q_{POC}=\Im\sum_k U_{POC,k}I_{grid,k}^*$. The LCL midpoint capacitor makes $I_{converter}\ne I_{grid}$. Consequently, a 600 var converter-target command can coexist with approximately 2103 var of POC injection. This is not a reactive-tracking error at the declared current target.

For the converter-target reproduction, the example stamps the general free-Q policy, adds the command's Q relationship at the matching location and maximises POC export. The converter's internal-terminal Q is a third quantity because its voltage includes filter drops. The tests independently verify all three power definitions, feeder KVL and the capacitor relation $I_{converter}-I_{grid}=Y_{mid}U_{mid}$.

network = ibr_network_reproductions()
for row in network.pairs
    @assert row.forward.solve.publishable && row.constrained.solve.publishable
    if row.expected == :agreement
        @assert row.p_error_W < .2 && row.q_error_var < .2
        @assert row.current_error_A < .001 && row.voltage_error_V < .001
    else
        @assert row.q_error_var > 1000.
    end
end
[(case=r.id, expected=r.expected, delta_P_W=r.p_error_W,
  delta_Q_var=r.q_error_var) for r in network.pairs]
4-element Vector{@NamedTuple{case::Symbol, expected::Symbol, delta_P_W::Float64, delta_Q_var::Float64}}:
 (case = :lcl_converter, expected = :agreement, delta_P_W = 0.07766027646130169, delta_Q_var = 0.01582530562654938)
 (case = :lcl_poc_q_mismatch, expected = :different_q_location, delta_P_W = 0.7130628284417071, delta_Q_var = 1503.0990363203603)
 (case = :lcl_grid, expected = :agreement, delta_P_W = 0.07757325379634494, delta_Q_var = 0.015715040256168322)
 (case = :unbalanced_reduced, expected = :agreement, delta_P_W = 0.07788274053518762, delta_Q_var = 0.01571499660781228)

The matched cases agree within 0.2 W/var, 1 mA and 1 mV. The unmatched Q locations differ by about 1.5 kvar despite both solves being feasible. Here maximum export also reproduces the source-limited active dispatch; that selection is conditional on the same source budget and inactive other limits.

Saturation and infeasibility are different outcomes

The remaining cases deliberately exercise three different situations:

CaseForward modelOptimisation modelIndependent explanation
Unbalanced 207 V feeder with a binding conductor limitVar-priority apparent-power allocation followed by current backoff reduces P and QStrict POC Q=2640 var, maximum P retains Q and curtails more PDifferent operating relationships on the same physical plant
Requested Q=7200 var on a lossless 6000 VA plantLimiter backs off the requestStrict Q service is infeasible``
Grounded LCL shunt, three-leg bridge, nonzero POC $U_0$ and balanced grid currentA corresponding exact zero-sum grid-current command has the same circuit obstructionThe tested balanced-grid constraints are infeasibleCapacitor zero-sequence current has no path consistent with both imposed current sums
saturated = network.saturated
@assert saturated.forward.solve.publishable && saturated.constrained.solve.publishable
@assert saturated.constrained.plant.q_poc-saturated.forward.plant.q_poc > 15.
@assert saturated.forward.plant.p_poc-saturated.constrained.plant.p_poc > 5.
@assert !network.impossible_service.constrained.solve.publishable
@assert !network.zero_sequence.balanced.solve.publishable
@assert network.zero_sequence.released.solve.publishable
(forward=(P_W=saturated.forward.plant.p_poc,Q_var=saturated.forward.plant.q_poc),
 strict_q=(P_W=saturated.constrained.plant.p_poc,Q_var=saturated.constrained.plant.q_poc),
 impossible_Q=network.impossible_service.constrained.termination_status,
 incompatible_balance=network.zero_sequence.balanced.termination_status)
(forward = (P_W = 5344.864180231648, Q_var = 2618.871639181803), strict_q = (P_W = 5334.814152002999, Q_var = 2639.9999999999995), impossible_Q = "LOCALLY_INFEASIBLE", incompatible_balance = "LOCALLY_INFEASIBLE")

The last case fixes POC phasors to isolate the circuit obstruction, adding a 3 V zero-sequence voltage to the unbalanced source. Balanced grid current has $I_{0,grid}=0$. Identical grid-arm impedances then give $U_{0,mid}=U_{0,POC}=3$ V. The grounded capacitor requires $I_{0,shunt}=Y_{mid}U_{0,mid}\ne0$, while three-leg topology requires $I_{0,converter}=0$. Midpoint KCL would require $0=0+I_{0,shunt}$, a contradiction. This is an analytical obstruction, not a conclusion inferred only from a local solver status.

Switching the allocation to balanced converter current restores a path: the grid arm carries $I_{0,grid}=-Y_{mid}U_0/(1+Y_{mid}Z_{grid})$. The paired solve and test verify that complex current. This changes the operating assumption while retaining the physical plant. It does not make every infeasible service request feasible.

These cases complement the fixed-measurement sequence-priority example above. They do not establish arbitrary unbalanced sequence-controller equilibrium equivalence, dynamic stability, or exact-versus-smooth network fixed-point equivalence. The quantities checked here are separately solved smooth-model operating points and independently evaluated circuit/capability identities.
